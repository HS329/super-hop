# SUPER HOP — 「そらへのぼる町」

Three.jsで制作した、**登るだけの3Dアクション**。ジャンプはありません。背中に負ったすいとりポンプが、上へ行く唯一の手段です。はじめは**何もない地面**に立っています。そこには落ちる場所がありません。木箱、藁の山、樽、切り株、家根と、地面から続く足場をポンプで渡っていけば、そのまま町の広場に出られる——それがチュートリアルです。広場から先は、家根や庭先道具、浮島、岩棚、尖岩、雲を伝わって、81m上の頂上の旗へ。道は1本ではありません。まわりには**乗れるもの**がいっぱい有るので、横へ跳んで、足場から足場へ、自分で道を作りながら登ります。外しても死にません——**いちばん下の地面まで落ちて、そこに立つ**だけです。キャラクター・町・足場・空・効果音まで、すべてコードで生成しています（外部アセットなし）。

「ジャンプキングを3Dにしたら、あのひたすら上へ進む感覚そのものだった」というのがこの面の発明です。あのゲームでジャンプだったものを、ここではポンプが担います。そして『Only Up』のように、**決められた階段を登るのではなく、周囲の足場を横にも使いながら自分で道を作って登る**面になっています。

面は**ひとつだけ**作りこんでいます。難易度セレクトはありません。

## 起動

リポジトリのルートで実行します。

```powershell
npm run dev:hop
```

ブラウザで `http://127.0.0.1:5175/platformer/` を開いてください。このリポジトリはSUPER HOP単体なので、この1本だけです。

## 操作

| キー | 動作 |
| --- | --- |
| WASD / 矢印 | 移動（倒した方向＝画面の奥へ進む。下の「移動は、いつも画面の向き基準」参照）。**溜めている間は足が止まり、同じ入力が「狙い」になります** |
| **E / Space / RT** | **ポンプ**。押しっぱなしで圧が溜まり、離した瞬間に打ち上がる（下の「すいとりポンプ」参照）。ジャンプキーはありません |
| **Q / A（パッド）** | **ホバリング**。空中で一度だけ、押している間（最大1秒）落下を止めて水平に進む（下の「ホバリング」参照） |
| Shift | 走る（最高速 9.4。歩きの 5.6 に対して加速も上がります） |
| マウスドラッグ | カメラ回転 |
| ホイール | ズーム |
| C | カメラを背後に戻す |
| L | 表示言語の切り替え（日本語 ⇄ English） |
| M | 音のON / OFF |
| Esc | 一時停止・再開 |
| R | 頂上到達後の再挑戦 |
| Enter / Space | タイトル画面でスタート |

物理は120Hz固定ステップ。薄い動く足場を突き抜けず、足場と一緒に動けばそのまま運ばれます。タブから離れると自動で一時停止します。

## 「そらへのぼる町」の中身

面は頂上81m（設計上の登り高さは78m、頂上の足場ぶんだけ実際に届く位置が上になります）、本道23ホップ。生成はシード付きで、誰が起動しても**まったく同じ面**が開きます（検査も同じ道を歩けるように）。下から上へ、標高ではなく**登り切った割合**で帯に分かれています。いちばん下には、塔とは別に**地面**があります。

| 帯 | 高度 | 足場になるもの |
| --- | --- | --- |
| 地面 | −3m | 幅124mの平野。ここには落ちる場所がない |
| 町 | 0〜16m | 広場（20×20m）、木箱、樽、馬車、家根、切り株、藁の山 |
| 浮島 | 16〜37m | 浮島、板渡し |
| 岩 | 37〜61m | 岩棚、尖岩 |
| 雲 | 61〜81m | 雲の足場、頂上の旗 |

- プレイヤーは**平野の地面**に立って始まります。足場は5つ、地面に載った庭先道具（木箱→藁の山→樽→切り株→屋根）だけ。これをポンプで渡っていくと、最後の屋根が広場と同じ高さになるので、そのまま町に入れます。**チュートリアル専用に用意した道**で、各Hopはチャージ3〜4割で届きます（`npm run check:climb` と `verify:hop` が実際に渡り切って確認している）。
- 本道は23ホップ。**ほかに横道が9本**、本道の途中から横へ伸びています。近道にも、ただの加点にもなる。横道も含めて**全部の足場が「満タンのポンプで届く」ように配置を検証**してから面を確定しています（`npm run check:climb`）。
- 広場には9個の庭先道具が散らばっていて、これ自体が最初の足場になります。広場の端から跳んで、最初の木箱へ。
- 各段の**コインは、次の足場へ届く放物線そのもの**に沿って並んでいます。軌道の案内なので、コインをたどれば届く。横道にも3枚ずつ。チュートリアルにも、同じ案内が並んでいます。
- 3ホップに1か所、**動く足場**（本道3か所）。上に乗れば運ばれ、降りれば止まります。
- **消える足場**3か所。周期3秒で6割の実体化。大穴をショートカットできる近道ですが、上で消えると落ちます。消える直前に点滅して合図を出します。
- **風**が実際の力としてかかりつづけます（強度1.0）。空中でのみ効き、方向はゆっくり変わっていくので、同じ撃ち方でも着点が少しずつずれます。HUD右上に**風向の矢印**（画面の向きでの表示）が出ます。
- 頂上には旗と輪になったコイン、四方の柱。到達で +5000点。

足場はすべて**厚みのある板**です。板の裏に頭をぶけないには、輪郭に触れるまでに足が板の高さへ届いていなければならない。なので「水平距離だけ届く」では足りず、**縁より上で越えてから落ちる**軌道でなければなりません。面の生成と検査は全部この条件で解いています。

## すいとりポンプ

『スーパーマリオサンシャイン』のあいつを、そのまま背中に負っています。

- **`E` / `Space` / RT を押しっぱなし**にすると、地面に足をついたまま圧が溜まります。1.25秒で満タン。HUDの `PUMP` ゲージが青から金色に変わり、タンクの帯が発光し、ノズルから水が垂れます。
- **離した瞬間**に打ち上がります。到達高度は `満タンで17m = 身長（1.7m）× 10体分` から逆算して発射速度を決めているので、**半分なら約4.3m、3割なら約1.5m**。溜め方がそのまま到達高度になります。
- **溜めている間は足が止まります。** そのあいだ倒している方向は「体の傾き」になり、最大54°まで狙を付けられます。傾けたぶんだけ横に届き、そのぶん登れる高さは減る（45°なら半分、54°なら約3.5mぶん）。**高さか、届きか**を毎回選ぶゲームです。
- **弾道のガイドはありません。** 離す前に線や着点リングを出していましたが、今はありません。届くかどうかは、コインの弧と、自分の体で確かめるものになっています。
- **空中では少しだけ舵が取れます。** 発射の向きを大きく変えることはできませんが、着点を少しずつ寄せられる。発射で得た横速度は打ち消さない上限をかけてあるので、舵で減速することはありません。
- 空中で押し始めても圧は作れません（チャージは地面に立っている間だけ）。

## ホバリング

`Q`（パッドではA）を、**空中で**押している間だけ、落下が止まります。

- **1回の空中で1回だけ。** 使い切ると、地面に立つまで戻りません。HUDの `HOVER` ゲージが残りを示します（地面では満タン、空中では金色に減っていく）。
- **長くて1秒。** 押しているあいだ縦の速度は −2.4〜+1.2 m/s に保たれるので、落下はほぼ止まり、少しだけ沈みます。1秒経つか、指を離すと終わり、そのまま落ちます。
- **水平に進むための操作です。** 押している間は空中の舵が強力になり（加速度26、上限11m/s）、届かない1mを稼げる。発射で得た横速度はやはり打ち消しません。
- 地面で押しても何も起きません。チャージにもなりません。
- 難易度のため、ガイドラインはこのとき消しました。ホバリングは「届かなかった1m」を取り戻す最後の一手なので、届くかどうかを自分で見当つけなければならないほうが面白いはずです。
- 実測（`npm run probe:hover` → `scripts/probe-hover-reach.mjs`）：広場からチャージ68%の扁平な一発を撃つと18.1m先へ着地します。同じ一発の頂点でホバリングすると33.7mまで滑る（**+15.6m**）。いちばん高いところはその間1mしか伸びないので、**ホバリングは高さではなく届きを増やす**道具だと数値でも分かっています。

## 落ちても終わらない

- **ライフも、タイムリミット、ゲームオーバーもありません。** 塔から落ちたら、**いちばん下の地面まで落ちて、そこに立ちます。** テレポートもリスポーンもありません。落ちた場所の真下に地面があるので、そこからまた登り直します。
- 地面の縁（幅124m）の外へ落ちた時だけ、いちばん近い地面の上に戻されます。それ以外の落下は、ただ落下です。
- 登りかけていた位置より **12m以上**落としたときだけ `FALLS` が1つ増えます。点数でも時間でもなく、**落としたぶんをまた登る**という事実のほうを数えています。
- 計測は**ストップウォッチ**です。HUDの `HEIGHT` は現在高度、右端の縦バーは最高到達の割合（上端が頂上）。**足場ごとに初めて触れたとき点数**が入るので（本道の足場 +300、庭先道具 +60）、登った距離と寄り道がそのまま点数になります。
- 頂上に到達すると、`スコア + 持ち時間ボーナス` が最終スコア。持ち時間ボーナスは `max(0, 320 − 実測秒) × 10`。**速いほど儲かる**だけで、遅くてもクリアはできます。

## 空と風

登っている実感は、HUDより先に空の色で伝えることにしています。登った割合に応じて空のグラデーション・霧の色と距離・光の強さが補間され、頂上に近づくほど空は濃く、眼下には雲の帯と町の広場が小さくなっていきます。雲は風に流れてゆっくり町のまわりを回ります。

## 移動は、いつも画面の向き基準

スティックや方向キーを倒した方向が、そのまま進む方向です。視点を真横に向け直せば画面の上側へ歩き、主人公の真正面から覗き込むように構えれば、前に倒したときは画面の奥へ下がります。カメラの角度がどれだけでも「画面で倒した方向へ進む」は変わらず、操作方向が変わるモードはありません。

**スティックの量は、そのまま速度にはなりません。** デッドゾーン（0.24）を越えたぶんを0〜1に伸ばしたあと、**2回かけてカーブを曲げ**、倒し始めをゆるくしてあります。半分に倒すと速度は約2割、最後まで倒して10割。だから「少し傾けただけで思いきり進んでしまう」ことがなく、着物の裾を直すような10cmの調整ができます。走る判定は逆に、最後まで倒し切ったときだけなので、走りたいときに誤爆しません。キーボードはそのまま段差のない入力で、スティックのカーブは効きません。

カメラは**手動操作だけ**です。勝手に回ったり追従したりしないので、見上げたい画角を固定したまま登れます。視点の操作はマウスドラッグ・ホイール・右スティック、`C`（パッドではB）でいつでも主人公の背後に構え直せます。タイトル画面ではゆっくりと自動で回っています。

## 表示言語

タイトル画面の `言語` ボタン、または `L` キー（パッドではX）で**日本語 ⇄ English**を切り替えられます。タイトル、操作案内、HUD、一時停止、頂上パネル、トースト、ページタイトルまで、画面中の文言がその場で切り替わり、選択は `localStorage` に保存されるので次回も同じ言語で開きます。面の名前も `そらへのぼる町 ⇄ SKYWARD TOWN` に変わります。文字列はすべて `platformer/i18n.js` の1つの表にまとめているので、言語を増やす場合は表を1枚足すだけです。

## コントローラー

Gamepad API に対応しているので、**接続した瞬間からそのまま使えます**（設定・ボタン割り当ての変更画面はありません）。タイトル画面の「CONTROLLER」行に認識された機器名が表示されます。標準割り当て（XInput相当）で読みます。

| パッド | 動作 |
| --- | --- |
| 左スティック / 十字キー | 移動。**溜めている間は狙い（体の傾き）になる**（デッドゾーン0.24を越えたぶんは2回かけてカーブを曲げるので、半分の倒し幅では速度は約2割。下の「移動は、いつも画面の向き基準」参照） |
| **RT（右トリガー）** | **ポンプ**。押しっぱなしでチャージ、離すと発射 |
| **A** | **ホバリング**（空中で一度だけ、押している間）。タイトル画面ではAがスタート |
| LT / LB / RB、または左スティックを最後まで倒し切る | 走る |
| 右スティック | 視点回転（移動には影響しません） |
| Start | スタート / 一時停止・再開 |
| B | カメラを背後に戻す |
| X | 表示言語の切り替え（日本語 ⇄ English） |
| Select | 音のON / OFF |

パッドでのポンプはRTだけです。Aは空中のホバリングに回してあるので、**「Aで溜めてAで飛ぶ」はできなくなりました**。トリガーを引いて溜め、離して飛び、届かなければA。役割を分けたほうが手元が迷わないはずです。

## 検証

```powershell
npm run build
npm run preview -- --configLoader native --port 5175
# 別のターミナルで、必要ならHOP_BROWSERにChrome実行ファイルを指定
npm run check:climb            # 面そのものの設計検査（ブラウザ不要）
npm run verify:hop             # 実プレイ検査
npm run shots:hop              # 各高度の景色写真を artifacts/ へ（見栄え用の補助）
npm run cover:hop              # itch.ioのカード比率（1260×780）で、計器を消した表紙画を撮る
npm run probe:hover            # ホバリングが伸びる距離を実測する補助プローブ
npm run exe                    # Windowsの .exe にまとめる（→ ./desktop の皮を使う）
npm run verify:exe             # exe同梱のweb/を、exe自身のサーバーで起動検査
```

`scripts/check-climb.mjs` はブラウザを起動せず、`level.js` が面を組み立てるのと同じ生成関数（`planClimb`）をそのまま実行して、**地面のチュートリアルから頂上まで一発ずつで届くか**を総当たりで解きます。各ホップについて「次の板の輪郭に、身体が触れるまでに足が板の高さへ届いているか」（厚い板の裏で頭をぶけない条件）と「着点が板の上にあるか」を満たす最小チャージを求め、届かない段は `届かない` として出します。足場の重なり・世界半径外へのはみ出し・罠の数もここで検査します。いまの面は本道23ホップ・横道9本・広場の庭先9個・チュートリアル5個の**合計47個の足場がすべて到達可能**で、本道でいちばん厳しい一発でもチャージ65%（満タンの65%）、**チュートリアルは3〜4割**です。面の寸法や段数を変えたときは、これを回してから実プレイ検査へ進んでください。

`scripts/verify-hop.mjs` は実際のキー入力で、起動 → 面の生成（本道23ホップ・足場47個・頂上81m。地面の高さと平野の広さ、チュートリアル足場が5個あること、**火の玉が存在しないこと**） → **ジャンプが存在しないこと**（Spaceを叩いても足が地面から離れない） → **ポンプ**（1.4秒で満タン、離して**17m前後**打ち上がり、真上撃ちで横へ進むのは風だけ。溜めている間は足が止まり、倒した方向で体が傾き、**弾道ガイドは出ていないこと**。傾けると9m未満しか登らず12m以上横へ届く＝**高さと届きの交換**が実測される） → **チュートリアルを渡り切る**（スタート地点の地面から木箱→藁→樽→切り株→屋根まで、`debug.hopTo` が解いた一発で**実際に5段すべてに着地**。各Hopのチャージは6割以下。最後の屋根は広場と同じ高さに出る） → **落ちても終わらない**（塔から落とすと**地面まで落ちて、そこに立つ**。テレポートしていないので落ちた場所の真下にいる。`FALLS` が増えてHUDに出る。平野の縁の外へ落とすと、いちばん近い地面の上に戻される） → **空中の舵**（無入力では真上真下、入力では横に寄る） → 高度HUD（表示している数値が実際の高度と一致すること） → **ホバリング**（地面では使えない。空中で押し続けると約1秒間 `vy` が −2.4〜+1.2 m/s に保たれて高度を維持し、横には4m以上進む。息が切れると自分で終わり、その空中では戻らない。着ると戻る） → **スティックの感度**（仮想パッドを半分に倒すと、最後まで倒したときの移動量の45%未満で進む＝微調整が効く） → 音の切替 → ポーズ/再開 → **広場から頂上まで本道を実際に一発ずつ撃って登り切る**（各ホップで `debug.hopTo` が解いた発射がチャージ100%以内に収まること、その足場へ実際に着地していることを23段すべてで確認。頂上はゴール判定で登り切り、結果パネルに面の高さが出る） → リトライでの状態と面の復元 → **罠**（消える足場が周期で当たり判定を出し入れすること） → **風が実際の力**（同じ真上撃ちで横に流される） → **リロードしても面がまったく同じ**（`debug.route()` が一致） → 表示言語の切り替え（タイトル・案内・フッター・ページタイトルまで英語に変わり、`<kbd>`のキーキャップまで翻訳される。リロード後も記憶され、`L`で日本語へ戻せる） → ゲームパッド（仮想パッドを注入して、接続の自動検出・Aでスタート・左スティックで移動・RTでポンプの満タン発射17m・**Aはチャージにならないこと、空中でAを押すとホバリングが始まること**・右スティックで視点だけ動く・Startでポーズ/再開・Xで言語切替）までを確認します。検証画像は `artifacts/hop-*.png` に保存されます（タイトル `hop-title.png`、英語タイトル `hop-title-en.png`、チャージ中の狙い `hop-aim.png`、打ち上げ `hop-pump.png`、チュートリアル `hop-tutorial.png`、ホバリング `hop-hover.png`、落下後 `hop-fall.png`、頂上 `hop-summit.png`、パッド `hop-gamepad.png`）。`scripts/shots-hop.mjs` は各高度の画面を撮るための補助スクリプトです。

`window.__HOP__.snapshot()` は状態を読み取るだけの診断APIで、ゲームの状態を変更しません。`world`（面のkey） / `lang` / `route`（本道のホップ数） / `tutorial`（チュートリアル足場の数） / `tiers`（足場の数。頂上を含む） / `topHeight`（頂上の高さ） / `groundY`（地面の高さ） / `plainHalf`（平野の半径） / `height` / `maxHeight` / `bestTier` / `falls` / `blinkers` / `blinkersOn` / `movers` / `wind`（風向ベクトルと強度） / `pump`（現在のチャージ量・溜めている最中か・満タンの到達高さ `maxHeight` と最高記録） / `hover`（使えるか・最中か・使い切ったか、継続上限と縦速度の範囲） / `pad` / `camera` / `goal` / `spawn` を返します。`window.__HOP__.debug.teleport(x, y, z)` と `debug.setCamera(yaw, pitch, dist)` は検証用の強制移動とカメラ固定、`debug.setLang(key)` は言語の切り替え、`debug.tiers()` は各段の中心・高さ・寸法・種別・罠・横道・チュートリアルかどうか、`debug.route()` は本道の並び（この順に登れば頂上へ着く）、`debug.padPos(i)` はその足場の**いまの**当たり判定（動く足場は動いた位置を返す）、`debug.hopTo(i, tier)` は **本道i番目（`tier`を渡した場合はその足場そのもの）へ届く軌道を解いてそのまま発射する**検証用発射（板の輪郭を板の高さより上で越える軌道しか解かないので、その段が頭をぶつけずに登れるかそのものが測れる。届かなければ `{ok:false, reason:'no-arc'|'off-course'|'far-below'}`）、`debug.launchTo(x, y, z, over)` は「頂点が目標の over m 上を通る撃ち方」を解いて発射する検証用発射（射程外なら `{ok:false, reason:'too-far'|'too-steep'}`）、`debug.heldKeys()` はゲームが受け取っているキーの集合、`debug.hoverState()` はホバリングの入力要求・接地・継続時間を**物理ステップごとに**写した値（headlessでは入力の1フレームが飛ぶことがあるので、タイミングを突き合わせるための検査用）です。

## 他のPCへ渡す

画像も音もすべてコード生成なので、`dist` だけ渡れば動きます。外部サービスへの登録は不要です。

```powershell
npm run build          # dist/platformer/index.html に組み出す
npm run preview -- --configLoader native --port 5176   # dist をその場で配信
```

SUPER HOP だけを単体のzipにするなら：

```powershell
npm run build
npm run pack:hop       # share/super-hop/ に単体組み出し
Compress-Archive -Path share/super-hop -DestinationPath share/SUPER-HOP.zip -CompressionLevel Optimal
```

`share/super-hop/` は `index.html` と `assets/`（ゲームJS・three.js・CSS）と `README.txt` だけの自己完結フォルダーです。これをそのままzipにして送れば、受け取った側は**何かしらの静的サーバー**を通して開くだけで動きます（`file://` で直接開くとES modulesが読めません）。Nodeがあれば `npx serve .`、Pythonがあれば `python -m http.server 5176`、どちらも無ければ Netlify Drop / itch.io / GitHub Pages にフォルダーを置くだけで動きます。`vite.config.js` は `base: './'` にしてあるので、サブフォルダーやサブパスに置いてもアセットが壊れません。

`scripts/verify-pack.mjs` は、組み出した単体フォルダーを静的配信して、起動・面の生成（地面の高さと平野、チュートリアル足場が5個、スタートが地面にいること）・歩行・チャージ・17mの打ち上げ・**ホバリング**（空中で落下が保たれ、着ると戻る）まで確認するテストです（`node scripts/serve-static.mjs share/super-hop 5177` を別に起動してから `npm run verify:pack`）。

相手もNodeを使えるなら、ソース一式を渡して `npm install` → `npm run dev:hop` でも動きます（Node.js 20.19以降 / 22.12以降、WebGL対応ブラウザ）。同じLANの中で別のPCから遊ぶだけなら `npm run dev:hop:lan` で起動し、`http://あなたのIP:5175/platformer/` を開いてください。


## .exeで起動する（Windows）

`desktop/` に、Windowsに入っている **WebView2（Chromium）** を呼ぶだけの薄い皮を置いてあります。Chromiumを同梱しないので、出来上がるexeは約0.9MBです。

```powershell
npm run exe            # dist → share/super-hop → dist-exe/win/SUPER-HOP.exe と share/SUPER-HOP-win.zip
npm run verify:exe     # exeに同梱した web/ が、exe自身のサーバーだけで動くかの検査
```

`dist-exe/win/SUPER-HOP.exe` をダブルクリックするとウィンドウが開きます。中身はブラウザ版とまったく同じで、exeは空きポート（127.0.0.1）に小さなHTTPサーバーを立てて隣の `web/` を配るだけです。`file://` で開かないのでES modulesが動き、localhostは安全な起源なのでゲームパッドも言語設定の保存もそのまま使えます。

- 動くには Windows 10/11 の WebView2 実行時と **.NET Desktop Runtime 8**。無いマシンでは `npm run exe:self` で自己完結版（インストール不要。exe単体で約131MB、zipで約60MB）を作ります。どちらもウィンドウが開いて同じ動きをします
- **F11** でフルスクリーン、Alt+F4で終了。右クリックメニューやブラウザのショートキー（F12など）は止めてあるのでゲームの操作に邪魔されません。デバッグが必要なら `SUPER-HOP.exe --devtools`
- 言語設定などは exeと同じ場所の `data/` に保存されます（消すと初期状態に戻ります。書き込めない場所なら `%LOCALAPPDATA%\SUPER-HOP` に移ります）
- 実装は `desktop/Program.cs` 一ファイル。HTTPは http.sys を使わずソケットに直接話しているので、HTTPサービスが無効なマシンでも、管理者権限が無くても動きます。WebView2の初期化はウィンドウの `Load` で行っています（`Main` の中でawaitすると続行がMTAのスレッドに移り、COMが `RPC_E_CHANGED_MODE` で落ちる）

ElectronのようにChromiumを同梱しないから0.9MBで、そのぶんWebView2実行時に依存します（Windows 10/11なら普通入っています）。TauriはRustのツールチェーンが必要なので、このマシンでは作れていません。itch.ioに出す本体はHTML版（`share/SUPER-HOP.zip`）のままが便利で、Windows版は同じページの別のファイルとして添える形にできます。

## 構成

- `platformer/main.js`: 物理・衝突・状態遷移・入力（キーボード / マウス / Gamepad API。スティック入力はデッドゾーン後に2回かけてカーブを曲げる）・ポンプのチャージと発射と狙い・空中の舵・ホバリング（空中で一度、最大1秒）・落下（地面まで落ちて立つ。平野の縁の外だけ最も近い地面へ）・風・登り切った割合にあわせた空の色・HUD・合成音
- `platformer/level.js`: 面の組み立て。`planClimb()` がシード付きで本道と横道と庭先を配置し、**置いた足場そのものをHopの式で解いて届かないものは置き直す**。そのあと罠（動く／消える足場）を空きから補充し、頂上を置く。いちばん下には幅124mの平野（`GROUND_Y`）を敷き、その上に載る5個のチュートリアル足場（`TUTORIAL`）を本道の後に並べる（配置順を後ろに足すので、塔の形は変わらない）。Canvasで生成する木箱/岩/雲などのテクスチャもここ
- `platformer/world.js`: この面ひとつの設定（段数・高さ・一ホップの最大登り・リーチ・罠の数・風・par）。面を増やすならここにプリセットを足す
- `platformer/models.js`: ヒーロー（背中のタンクとホース、ノズル付き）・コイン・消える足場・頂上の旗の procedural モデル
- `platformer/i18n.js`: 表示言語（日本語 / English）の文言表と切り替え。HTML側の `data-i18n` キーに対応させる
- `platformer/index.html` / `platformer/style.css`: UIとHUD（高度・落下・風向・ポンプゲージ・ホバーゲージ・縦の高度バー）、面紹介、言語のセレクト、コントローラー接続表示

外部モデル、画像、音源は使いません。BGMと効果音はWebAudioで合成したチープな波形です。装飾フォントだけGoogle Fontsから取得し、未接続時はシステムフォントに切り替わります。

これは1本の面のプロトタイプです。2本目の面、セーブデータ、タッチ端末用の仮想ボタンは含みません。WebGL対応のブラウザが必要です。
